# 모구 가계부 🌱

치이카와 감성에서 영감을 받은, 로컬 우선 개인 가계부 및 자산관리 웹 앱입니다. 사용자가 제공한 치이카와·하치와레·우사기 이미지를 앱에 포함하여 표시합니다. React 19, TypeScript, Vite, Tailwind CSS 4, Recharts를 사용하며 로그인·백엔드·금융 API 없이 동작합니다.

## 실행

Node.js 22.12 이상 또는 24 LTS와 npm이 필요합니다. 검증한 환경은 Node.js 24.19.0입니다.

```sh
cd /workspace/codex
npm ci --cache /workspace/.npm-cache
npm run dev -- --port 5173
```

일반 PC에서는 저장소 폴더에서 `npm ci` 후 `npm run dev`를 실행하면 됩니다. 개발 서버 기본 포트는 5173입니다.

```sh
npm test           # 계산·검증·IndexedDB 테스트
npm run build     # TypeScript 검사 + 정적 배포 빌드
npm run preview   # 빌드 결과 실행
npm run test:e2e  # 실제 Chromium UI·브라우저 재시작 테스트
```

E2E는 기본적으로 `/usr/bin/chromium`을 사용합니다. 다른 위치에 설치했다면 `CHROMIUM_PATH=/실제/경로 npm run test:e2e`를 실행하세요. 앱 실행 자체에는 Chromium 설치가 필요하지 않습니다.

`dist/`를 정적 호스팅에 배포할 수 있습니다. API 서버나 비밀키는 필요하지 않습니다. 금융 기록은 호스팅 서버로 전송하지 않으며 외부 분석·광고·폰트 서비스도 사용하지 않습니다. 접속한 호스트와 포트가 달라지면 브라우저 저장소도 달라집니다.

## 처음 사용하기

1. **자산 → 계좌 등록**에서 계좌별 시작 잔액과 기준일을 입력합니다. 기준일의 첫 거래 직전 잔액입니다.
2. 어디서든 **거래 추가**를 눌러 수입·지출·계좌이체·카드대금을 기록합니다.
3. **홈**에서 이번 달 소비와 실제 현금흐름을 함께 확인합니다.
4. **설정 → JSON 전체 백업**으로 정기적으로 기록을 보관합니다.

빈 상태로 시작합니다. 화면을 먼저 체험하려면 **설정 → 샘플 데이터 불러오기**를 이용하세요. 한국 원화 샘플이 현재 월과 전월에 맞춰 생성됩니다. 기존 기록이 있으면 교체 확인을 거칩니다.

상단에서 조회 월을 선택합니다. 홈의 **현재 총자산**과 자산 화면의 계좌 잔액은 오늘 기준이며, 홈 하단 자산 요약은 **선택한 월말 기준**입니다. 화면에 기준을 각각 표시합니다. 부채를 관리하는 순자산이라는 표현은 사용하지 않습니다.

## 계산 규칙

금액은 모두 **안전한 정수 원화**로 저장합니다. 거래 1건·계좌 잔액의 허용 범위는 최대 1조 원입니다. 금액에 소수나 음수 지출은 입력할 수 없습니다.

```text
계좌 잔액 = 시작 잔액
          + 수입 − 직접 결제 지출
          − 이체 출금 + 이체 입금
          − 신용카드 대금 결제
          + 투자 평가손익

월 소비 = 해당 월의 지출 거래 합계 (신용카드 사용 포함)
월 현금흐름 = 수입 − 직접 결제 지출 − 카드대금 결제
총자산 = 등록한 모든 계좌의 잔액 합계 (부채 차감 전)
카드 미결제액 = 신용카드 사용 합계 − 카드대금 결제 합계
```

- 계좌이체는 **출금·입금 계좌를 연결한 거래 하나**입니다. 적금 납입도 이체로 입력하며, 총자산·소비·외부 현금흐름에 영향을 주지 않습니다.
- 계좌의 현재 잔액을 직접 덮어쓰지 않습니다. 모든 잔액은 원장으로부터 재계산하므로 거래 수정·삭제 시 양쪽 계좌와 월별 통계에 반영됩니다.
- 신용카드 사용은 **지출 + 신용카드(미결제)**로 입력합니다. 소비와 전체 미결제액에만 반영합니다. 실제 출금일에는 **카드대금**으로 입력하여 계좌만 차감합니다. 같은 금액을 일반 지출로 다시 입력하면 안 됩니다.
- 카드대금이 해당 날짜의 미결제액보다 크거나, 결제된 카드 사용을 삭제·감액하여 과거 미결제액이 음수가 되면 저장을 거부합니다. 같은 날은 사용을 결제보다 먼저 계산합니다.
- 자산 화면의 카드 미결제액은 총자산에서 차감하지 않으며 별도로 표시합니다. 현금성 자산 사이 이체는 현금흐름에서 제외합니다. 예적금·투자 계좌도 내부 계좌입니다.
- 투자 평가금액 갱신은 **오늘의 목표 평가액 − 오늘의 계산된 잔액**을 평가손익 기록으로 추가합니다. 수입·소비와 분리합니다. 실제 입출금은 수입/지출/이체로 별도 입력합니다.
- 과거 거래를 바꾸면 이전의 평가손익 금액은 유지하고 잔액에 변경분을 반영합니다. 목표 평가액으로 고정하는 방식이 아닙니다. 필요한 경우 현재 평가금액을 다시 갱신하세요.
- 월말 스냅샷은 종료된 지난달까지만 수동 생성합니다. 이후 거래·계좌·평가 기록 수정 시 기록된 월말 잔액도 자동 재계산합니다. 이는 변경 불가능한 감사 기록이 아닌 월말 자산 추이용 자료입니다.
- 시작일 이전의 거래, 미래 거래, 없는 계좌 참조, 같은 계좌 사이 이체, 중복 ID, 비정상 날짜·금액 등을 거부합니다.
- 7일 구간 합계는 매월 1–7일, 8–14일 등의 구간입니다. 일 평균은 월 전체 일수, 주 평균은 일 평균 × 7로 계산합니다. 전월 소비가 0원이면 증감률을 표시하지 않습니다.
- 연결된 거래·평가손익·스냅샷이 있는 계좌는 삭제를 막아 데이터가 끊기지 않게 합니다. 거래·계좌 삭제와 전체 초기화에는 확인이 필요합니다.

## 저장·백업과 데이터 보호

- IndexedDB의 `mogu-ledger` 데이터베이스에 원장 전체를 단일 트랜잭션으로 기록합니다. 저장 성공 후에만 화면 상태를 갱신합니다.
- 저장소를 열지 못하거나 저장이 실패하면 오류를 표시합니다. 기록을 잃을 수 있는 임시 메모리 모드로 조용히 전환하지 않습니다.
- JSON 복원은 파일 크기(20MB), 스키마 버전, 필드 타입·정수, 날짜, 중복 ID, 계좌 참조, 카드 결제 무결성, 스냅샷 합계를 검사한 뒤 **전체 교체 확인**을 받습니다. 검증 실패 시 현재 기록을 유지합니다.
- CSV는 한국어 UTF-8 BOM을 포함하고 따옴표·줄바꿈을 이스케이프합니다. 수식으로 해석될 수 있는 시작 문자를 방어합니다. CSV는 거래 내역용이며 전체 복원은 JSON으로 합니다.
- 파일은 사용자가 직접 관리합니다. 브라우저 데이터 삭제·시크릿 모드 종료·기기 변경에 대비해 JSON을 별도로 보관하세요.
- 로컬 저장은 암호화를 뜻하지 않습니다. 계좌번호·비밀번호를 입력할 필요가 없고, 백업에는 거래명이 포함되므로 파일을 안전하게 관리하세요.

## 검증

- 단위·저장소 테스트 20개: 수입·지출, 적금 이체, 이체 수정·삭제, 과거 거래의 월 변경, 카드 사용·대금 결제 중복 방지, 과다 결제 거부, 평가손익, 월말 스냅샷, 잘못된 백업, CSV 안전 처리, 저장 후 재로드.
- Chromium E2E 3개: 실제 UI로 계좌/거래 생성·수정·삭제, 이체·카드 처리, CSV/JSON 흐름, 새로고침, 백업 복원과 손상 파일 거부, 5개 화면·390px 모바일, 브라우저 완전 종료 후 재실행 시 데이터 유지.
- TypeScript 검사 및 프로덕션 빌드.

## 현재 버전의 범위

- 개인이 **한 브라우저 탭에서 사용하는 방식**을 기준으로 합니다. 여러 탭에서 동시 편집하면 마지막 저장이 앞선 편집을 덮어쓸 수 있습니다.
- 은행·카드 자동 연동, 로그인·클라우드 동기화, 부채·대출·순자산 계산, 카드별 청구주기·할부·한도·기존 미결제액 입력은 지원하지 않습니다. 기존 미결제액이 있다면 완전한 카드 잔액을 나타내지 않습니다.
- 반복 입력값은 제안하지만 자동 반복거래 생성·예산 목표·알림은 제공하지 않습니다. 환불은 별도의 기능이 없으므로 원래 지출을 수정하고 메모를 남기는 방식으로 관리하세요.
- 잔액이 부족한 거래도 입력할 수 있으며 음수 잔액이 표시될 수 있습니다. 이는 대출·부채 관리 기능을 의미하지 않습니다.
- PWA 설치·네트워크 없는 최초 로딩을 위한 서비스 워커는 없습니다. 로컬 우선은 데이터의 브라우저 저장과 서버 미전송을 의미합니다.
- 화면은 한국어·원화 전용이며 거래 날짜는 사용자의 브라우저 현지 날짜를 기준으로 합니다.
